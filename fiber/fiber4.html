fiber 之前的协调， React 会递归的比较 Vdom 树， 找到需要变更的节点，然后同步他们， 这个过程React过程为协调 (递归调用，不能中断) 在协调期间， React 会一直占用浏览器资源，会导致用户触发的事件得不到响应， 并且可能会掉帧，卡顿 一个虚拟DOM 算一个链表节点，同时，也是一个工作单元 fiber 解决了执行栈不能中断的问题 // 每次渲染有两个阶段 协调render 函数阶段(reconciler)和提交阶段(commit) // 可以认为是 diff 阶段，这个阶段可以被打断，此阶段找到所有的节点变更 (节点新增，删除，属性变更，这些变更成为 副作用 effect) // commit 不能被打断 (把上一个阶段计算出来的 需要处理的副作用 effect 一次性执行了，这个阶段需要同步进行，不能被打断) // 一个节点遍历完成的条件， 自己所有的子节点都完成算完成
